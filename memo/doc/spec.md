# mase 仕様

Android 用のシンプルなサウンドエディタ。Java で作る。

実装していないものには「（未実装）」と書いている。見出しに付いているときは、その節の全体が未実装。

## 動く環境
- Android 14 以降（minSdk 34）

## 機能
1 つの音声ファイルを読み込み、編集して、書き出す。機能はこの 3 つだけ。

- 読み込み：音声ファイルを 1 つ読み込む
  - 「開く」ボタンを押して、Android 標準のファイルを選ぶ画面で選ぶ（「読み込みの画面」）
  - 入力が 3ch 以上のときは、読み込むチャンネルを 2 つまで選ぶダイアログを出す（「内部の音声データ」）
  - 長い音声は、上限で打ち切って警告を出す（「音声データの長さの上限」）
- 編集：読み込んだ音声を編集する
  - データの量が増える編集でも、上限を越える分は末尾を切り捨てて警告を出す（「音声データの長さの上限」）
  - チャンネル数変換コマンド：チャンネル数（モノラル・ステレオ）を変える。「チャンネル数の変更」のこと（「編集コマンドのボタン群」の「全体の加工」）
  - レート変換コマンド：サンプリングレートを変える。「サンプリングレートの変更」のこと（「編集コマンドのボタン群」の「全体の加工」）
  - ほかの編集コマンドは「編集コマンドのボタン群」
  - 編集を元に戻せる（「元に戻す」）
- 書き出し：編集した音声をファイルに書き出す
  - 「保存」「名前を付けて保存」「選択範囲を保存」の 3 つのコマンドで行う（「編集コマンドのボタン群」）
  - 書き出す形式などのパラメータは「編集コマンドのボタン群」の「保存・名前を付けて保存・選択範囲を保存」
  - 書き出すときに、チャンネル数とサンプリングレートは変換しない。内部の音声データのチャンネル数・サンプリングレートのまま書き出す。変えたいときは、先に「チャンネル数の変更」「サンプリングレートの変更」を使う
  - 「保存」「名前を付けて保存」での書き出しの後、書き出した内容で内部の音声データを置き換えるかをダイアログで問う。「選択範囲を保存」では問わない（内部の音声データは変えない）
    - 置き換える：内部の音声データを、書き出した内容にする。書き出したファイルを読み込んだのと同じに扱い、保存済みになる
    - 置き換えない：内部の音声データは書き出す前のまま
    - メッセージは「保存した内容で、編集中の音声データを置き換えますか？」、ボタンは「置き換える」「置き換えない」（文言は案）
  - このダイアログを出すのは、書き出すと音が変わる形式（mp3・m4a、wav の 8 ビット）のときだけ。wav の 16 ビットは内部の音声データと同じ内容なので、出さない（仮。ユーザーに確かめていない）

## 扱う音声ファイル

| 形式 | 扱い |
|---|---|
| wav | |
| mp3 | |
| mp4 | 音声トラックだけを扱う |

形式の名前の書き分け（アプリの文言、README、このドキュメントで共通）。

| 言葉 | 意味 | 使う所 |
|---|---|---|
| mp4 | 入れ物（コンテナ）の形式。動画と音声が入る | 読み込みの説明。動画の入った `.mp4` も開ける（音声トラックだけを使う）。`.m4a` も、mp4 の一種として開ける |
| m4a | 音声だけが入った mp4 のファイルに付ける拡張子 | 保存の説明と、保存の形式の選択肢。保存でできるファイルは、拡張子が `.m4a` で、中身は音声だけ |
| AAC | m4a の中の、音声の圧縮方式 | 圧縮方式を説明する所だけ（「m4a（AAC）」など）。選択肢やメッセージの、形式の名前には使わない |

- 保存については、「mp4」とは書かない（動画のファイルができるように読めるため）。以前は、「mp4」「mp4（m4a）」「m4a」が混ざっていた

## 内部の音声データ
読み込んだ音声は、次の形でアプリの中に持つ。

| 項目 | 持ち方 | 変わるとき |
|---|---|---|
| サンプルの形式 | 16bit signed。入力の形式に関わらず、読み込むときに変換する | 変わらない |
| チャンネル数 | モノラル（1ch）・ステレオ（2ch）を入力のまま持つ | 「チャンネル数の変更」（チャンネル数変換コマンド） |
| サンプリングレート | 入力のまま持つ | 「サンプリングレートの変更」（レート変換コマンド）。「再生レートの変更」 |

- ファイルに書き出すときは、チャンネル数もサンプリングレートも変換しない
- 入力が 3ch 以上のときは、読み込むチャンネルを選ぶダイアログを出す。選べるのは 2 つまで
  - 1 つ選ぶとモノラル、2 つ選ぶとステレオとして持つ
  - 2 つ選んだときは、番号の小さいほうを L、大きいほうを R にする
  - ダイアログの題は「読み込むチャンネル（2 つまで）」、項目は「チャンネル 1」「チャンネル 2」…。1 つか 2 つ選んでいるときだけ「OK」を押せる（文言は案）
- 読み込みには、Android 標準の機能（MediaExtractor・MediaCodec）を使う
  - 入力のサンプルの形式は、8bit・16bit・24bit・32bit・浮動小数点を 16bit に変換する。24bit・32bit は上位 16bit を使う（ディザはかけない）
  - 途中でチャンネル数やサンプリングレートが変わる音声は、扱えない形式として読み込まない

### 音声データの長さの上限
内部の音声データの長さは、次の 2 つのうち短いほうまで。越える分は、末尾を切り捨てる。

| 上限 | 値 |
|---|---|
| 時間 | 10000 秒未満 |
| サンプル数 | 1000000000 サンプル未満 |

- 確かめるのは、読み込みのときと、データの量が増える編集のとき
- 切り捨てたときは、警告「データが長すぎます。末尾データをカットします。」を、「OK」で閉じるダイアログで出す
- 上限は、データ位置の表示の桁数（秒は整数部 4 桁、サンプルは 9 桁）に合わせている
- サンプル数は、1 チャンネルあたりで数える

## 元に戻す
編集を元に戻す機能（アンドゥ）と、元に戻した編集をやり直す機能（リドゥ）を持つ。

- 音声データが変わるたびに、音声データを、開始位置・終了位置といっしょに履歴に保存する
- 履歴は、リングバッファで持つ。保存できる数（元に戻せる最大回数）は、設定画面で変えられる（「設定画面」）
  - 最大回数を越えたら、古いものから捨てる
  - メモリが足りなくなったときも、古いものから捨てる
  - 最大回数は 0～99。最初の値は 10。0 にすると、履歴を保存しない（元に戻せない）
  - 履歴に保存する音声データは、できるだけ差分（変わった部分だけ）で持つ
  - 音声データ全体が変わる編集は、全体を差分として持つ
  - 履歴を 1 つも保存できないほどメモリが足りないときは、その編集をやめて、メッセージを出す
    - メッセージ（案）：「メモリが足りないため実行できません。設定の「元に戻せる最大回数」を 0 にすると実行できることがあります。」
- 「再生レートの変更」も、履歴に保存する。サンプルのデータは変えないが、メタデータの変更として扱う
- 履歴を空にするとき
  - 音声ファイルを読み込んだとき
  - 書き出した内容で内部の音声データを置き換えたとき（読み込んだのと同じに扱うため）
- 元に戻した後に、やり直す以外の編集をすると、やり直しの分（元に戻す前の、先の編集）を捨てる
- 編集は、すべて「ある範囲を、新しい区間に置き換える」形で表す。履歴には、置き換える前の区間と後の区間、サンプリングレート、開始位置・終了位置を持つ
- コピーは音声データを変えないので、履歴に保存しない
- 元に戻す・やり直すを実行した後は、常に未保存の状態にする（保存した時点の内容に戻っても、保存済みにはしない）
- ボタンは、編集コマンドの「アンドゥ」のグループに置く（「編集コマンドのボタン群」）
  - 元に戻すものがないときは「元に戻す」を、やり直すものがないときは「やり直す」を、グレーにして押せなくする

## 再生
音声データを再生する。操作は、再生ビューのボタンで行う（「画面」の「再生ビュー」）。

- 再生する範囲は、開始位置から終了位置まで（選択範囲）
- 再生位置：今、再生している位置。停止すると、その位置で止まる
  - 再生ビューと波形ビューの両方に表示する
  - 再生ビューのタップやドラッグで、動かせる（シーク）。シークできる範囲は、開始位置から終了位置の間
  - 再生中に巻き戻しやシークをした後は、その位置から再生を続ける
  - 再生していない間に開始位置・終了位置を動かして、再生位置が選択範囲の外になるときは、再生位置を開始位置・終了位置でクリップする
- 再生位置が終了位置に来たとき
  - リピートがオフ：再生を止め、再生位置を開始位置に戻す
  - リピートがオン：開始位置に戻って、再生を続ける
- 再生中も、開始位置・終了位置は動かせる。動かした位置が再生する範囲に反映されるのは、次のとき
  - 再生ビューのボタンを操作したとき
  - リピートで、次の繰り返しを始めるとき（そのときの開始位置・終了位置を取り直す）
    - 今の繰り返しは、それまでの範囲の終わりまで再生する。終了位置を手前へ動かしても、今の繰り返しがそこで止まることはない
- 編集コマンドを開くと、再生は停止する

- 現在のサンプリングレートが、再生するハードウェアで指定できる値でないときは、再生できない
  - 入力のファイルのサンプリングレートがそのまま内部のサンプリングレートになるので、読み込んだ直後から再生できないことがある
  - 再生できないことを、一度だけ表示する
  - その後は、新しいデータを開くか、レートを変えるまで、再生しない。表示も繰り返さない
  - 表示は「このサンプリングレートでは再生できません。サンプリングレートを変更すると再生できます。」を、「OK」で閉じるダイアログで出す（文言は案）
  - 再生できるかどうかは、再生を始めるときに、そのサンプリングレートで音を出す準備ができるかで判定する
- 画面が見えなくなったとき（ほかのアプリに切り替えたときなど）は、再生を止める
- 再生中の再生位置の表示は、1 秒に約 30 回進める

## 画面
アプリの画面は 2 つ。起動すると、編集画面が出る。

| 画面 | 内容 |
|---|---|
| 編集画面 | 読み込んだ音声を表示・再生・編集・書き出しする。起動したときに出る |
| 読み込みの画面 | 音声ファイルを 1 つ選んで読み込む。編集画面の「開く」ボタンで出す |

- 起動した直後は、音声データを読み込んでいない。このときに使えるのは、「開く」ボタンとメニューだけ

| もの | 音声データを読み込んでいないときの表示 |
|---|---|
| データファイル名 | 「（音声データを開いていません）」 |
| 波形ビュー | 空。波形もバーも描かない |
| 再生ビュー | 空。波形もバーも描かない。右端のボタンは押せない |
| 編集コマンドのボタン群 | 「開く」だけ押せる |
| メニュー | 使える |

### 読み込みの画面
音声ファイルを 1 つ選んで読み込む画面。アプリが作る画面ではなく、Android 標準のファイルを選ぶ画面（SAF：Storage Access Framework）を使う。

- 編集画面で「開く」ボタンを押すと出る（「編集コマンドのボタン群」の「ファイル」）。起動したときには出ない
- ファイルを選ばずに戻ったときは、何もしない。「開く」を押す前の状態に戻る
- ファイルを選び終わるまでは、今の音声データを残す。途中でやめれば、元の状態に戻れる
- 読み込んでいる間は、「読み込んでいます…」と「キャンセル」ボタンのダイアログを出す。「キャンセル」を押すと、読み込みをやめて元の状態に戻る
- 読み込みの画面に出すのは、音声のファイルと mp4 のファイル

未保存の音声データがあるときに「開く」を押すと、読み込みの画面の前に、確認のダイアログを出す。

- メッセージ：「音声データが未保存です。保存しますか？」

| ボタン | 動き |
|---|---|
| 保存して開く | 「保存」ボタンを押したときと同じ動きをする。正常に保存できたときだけ、読み込みの画面に進む。保存できなかったとき・保存をやめたときは、進まない |
| 保存しないで開く | そのまま読み込みの画面に進む |
| キャンセル | 読み込みの画面に進まず、元の状態に戻る |

読み込めなかったときは、理由に合ったメッセージを出す。文言は案。

| 理由 | メッセージ |
|---|---|
| ファイルを開けない | 「ファイルを開けません。別のファイルを選んでください。」 |
| 扱えない形式 | 「この形式のファイルは開けません。wav・mp3・mp4 のファイルを選んでください。」 |
| ファイルが壊れている | 「ファイルが壊れているため開けません。別のファイルを選んでください。」 |
| 音声が入っていない | 「このファイルには音声が入っていません。別のファイルを選んでください。」 |
| メモリが足りない | 「メモリが足りないため開けません。ほかのアプリを終了してからもう一度お試しください。」 |

- 読み込めなかったときと、3ch 以上のチャンネルを選ぶダイアログでやめたときも、できる限り「開く」を押す前の状態に戻す（元の音声データ、開始位置・終了位置、未保存の状態など）
  - 元に戻すのは、明らかに戻せる場合だけ。それ以外（新しい音声を読み込む途中でメモリが足りなくなったときなど）は、元の音声データをあきらめる
- 読み込めなかったときのメッセージは、「OK」で閉じるダイアログで出す。元の音声データは残す
- 理由の分け方

| 理由 | 分け方 |
|---|---|
| ファイルを開けない | ファイルそのものを開けなかった |
| 扱えない形式 | ファイルの形式を判定できなかった。デコーダーがなかった。途中でチャンネル数やサンプリングレートが変わった |
| ファイルが壊れている | デコードの途中で失敗した。音声が 1 サンプルも取り出せなかった |
| 音声が入っていない | 音声のトラックがなかった |
| メモリが足りない | 音声データを置くメモリを確保できなかった |

- 未定のこと
  - 元の音声データをあきらめた後の編集画面の状態（音声データを読み込んでいない状態にするか）と、そのときの表示。今の実装では、新しい音声を読み終えるまで元の音声データを持ったままにしているので、メモリが足りないときも元の音声データは残る

### アプリの終了
未保存の音声データがあるときに、戻るボタンでアプリを終了しようとすると、「開く」のときと同じ確認のダイアログを出す。

- メッセージ：「音声データが未保存です。保存しますか？」

| ボタン | 動き |
|---|---|
| 保存して終了 | 「保存」ボタンを押したときと同じ動きをする。正常に保存できたときだけ、終了する。保存できなかったとき・保存をやめたときは、終了しない |
| 保存しないで終了 | そのまま終了する |
| キャンセル | 終了せず、元の状態に戻る |

- ボタンの文言は案（「開く」のときの「保存して開く」「保存しないで開く」に合わせた）
- 終了するときは、編集中の状態（音声データ、履歴、コピーバッファ）を捨てる。次に起動すると、音声データを読み込んでいない状態から始まる
- 未保存の音声データがないときは、ダイアログを出さずに終了する
- 戻るボタン以外でアプリが閉じられるとき（ほかのアプリに切り替えた後に、システムに終了させられたときなど）は、強制終了と同じに扱う。確認のダイアログは出さず、保存もしない。未保存の音声データは失われる

### 編集画面の並び
上から順に、次のものを並べる。

| 順 | もの | 内容 |
|---|---|---|
| 1 | データファイル名 | 読み込んだファイルの名前を表示する。同じ行の左端に、メニューのボタン（三本線）を置く（「メニュー」）。右端に、チャンネルのスイッチ「L」「R」を置く（「チャンネルのスイッチ」） |
| 2 | 波形ビュー | 読み込んだ音声の波形を表示する。まわりに縦の倍率バーとスクロールバーを置く（下の表） |
| 3 | 再生ビュー | 音声データ全体と、開始位置・終了位置・再生位置を表示する。右端に再生のボタンがある |
| 4 | 開始位置・終了位置の操作ボタン群 | 開始位置と終了位置を、ボタンと数値の入力で動かす |
| 5 | 編集コマンドのボタン群 | 編集コマンドを実行するボタンを並べる |

波形ビューのまわり。

| 位置 | もの |
|---|---|
| 波形ビューの右 | 縦の倍率バー |
| 波形ビューの左 | 余白。幅は、縦の倍率バーと同じ |
| 波形ビューと縦の倍率バーの間 | 余白。幅は、縦の倍率バーと同じ |
| 波形ビューの下 | スクロールバー（横の表示位置を動かす） |

データファイル名の表示。

| 状態 | 表示 | 例 |
|---|---|---|
| 音声データを読み込んでいない | 「（音声データを開いていません）」 | |
| 保存済み | ファイル名 | `voice.wav` |
| 未保存 | 先頭に「* 」を付けたファイル名 | `* voice.wav` |

- 音声データを読み込んでいるときは、ファイル名の後ろに、サンプリングレート、チャンネル数、音声データ全体の長さを表示する。形は「ファイル名 [サンプリングレートkHz/チャンネル数ch/秒数秒/サンプル数サンプル]」
  - 例：`voice.wav [48kHz/2ch/4.00000秒/192000サンプル]`、未保存なら `* voice.wav [48kHz/2ch/4.00000秒/192000サンプル]`
  - サンプリングレートは kHz で表し、末尾の 0 は付けない（44100Hz → `44.1kHz`、48000Hz → `48kHz`、22050Hz → `22.05kHz`、11025Hz → `11.025kHz`）
  - チャンネル数は、モノラルが `1ch`、ステレオが `2ch`
  - 秒数は、小数部 5 桁（開始位置・終了位置の表示と同じ）
  - 編集でサンプリングレート・チャンネル数・長さが変わると、表示も変わる
  - 表示する所は、編集できない入力欄にする。幅に収まらないときは、省略せず、指で横にスクロールして全体を見られる
    - 触ってもキーボードは出ず、文字は変えられない
    - 表示の内容が変わると、スクロールの位置は先頭に戻る
    - 以前は、ファイル名の中ほどを「…」で省略していた
- 保存済みになるのは、「保存」「名前を付けて保存」で正常に保存できたとき。「選択範囲を保存」では、保存済みにならない

未保存になる操作・ならない操作。

| 操作 | 未保存になるか | 理由 |
|---|---|---|
| 音声データを変える編集コマンド | なる | |
| 再生レートの変更 | なる | サンプルのデータは変えないが、メタデータ（サンプリングレート）を変えるため |
| 「保存」「名前を付けて保存」の後、書き出した内容で内部の音声データを置き換える | ならない（保存済みになる） | 書き出したファイルを読み込んだのと同じに扱うため |
| 選択範囲を保存 | 変わらない（未保存なら未保存のまま） | |
| 読み込むときの変換（16bit への変換、3ch 以上からのチャンネルの選択、長さの上限での打ち切り） | ならない | 読み込んだ直後は保存済み |
| 音声データを変えない操作（開始位置・終了位置の移動、倍率やスクロール、再生、コピー、無音区間・発音区間の選択、色の設定） | ならない | |
| 何もせずに終わった編集コマンド（ダイアログをキャンセルしたとき、音量の最大化で選択範囲がすべて無音のとき） | ならない | |
| 元に戻す・やり直す | なる | 安全のため、常に未保存にする（「元に戻す」） |

- 「保存」「名前を付けて保存」の後に、書き出した内容で内部の音声データを置き換えたときは、データファイル名の表示が、書き出したファイルの名前になる（書き出したファイルを読み込んだのと同じに扱うため）
- 「選択範囲を保存」は、ファイルに書き出すだけ。内部の音声データ・未保存の状態・データファイル名の表示の、どれも変えない。置き換えを問うダイアログも出さない
- 大きさを決める順（ユーザーの指示）。先に決めたものが場所を取り、波形ビューは残りを使う

縦向き。

### 画面の向き
画面は、端末の向きに合わせて、いつでも回転する。向きが変わると、その向きの並び（「編集画面の並び」の縦向き・横向き）で、画面を作り直す。

- 向きのほか、画面の大きさ（dp）や表示の密度が変わったとき（画面の分割、端末の表示サイズの設定の変更など）も、同じように画面を作り直す

- 以前は、起動したときの向きで固定していた。ユーザーの指示で、常に回転できるようにした
- 向きが変わっても、変わらないもの
  - 音声データ、開始位置・終了位置・再生位置、未保存の状態、履歴、コピーバッファ
  - 横の倍率（全体に対する割合）と表示位置、縦の倍率
  - 編集コマンドのグループの、開く・畳むの状態
  - 再生（再生中に回しても、再生は続く）
  - 出ているダイアログや設定画面（出たまま、新しい向きで表示される）
  - 実行中の編集（そのまま続く）
- 向きが変わると、元に戻るもの
  - データファイル名の表示の、横のスクロールの位置
  - 開始位置・終了位置の入力欄に、入力している途中の文字
  - バーのドラッグなど、指で操作している途中の動き

### ライトモード・ダークモード
画面の配色は、端末の設定（ライトモード・ダークモード）に合わせて、自動で変わる。

- 変わるもの：画面の背景、文字、ボタン、入力欄、ダイアログ、設定画面、アプリの情報、スクロールバー、縦の倍率バー、リピートがオンのときのボタンの色、画面の上下のバー（時刻や戻るボタンなど）の絵の色
- 変わらないもの：波形ビューと再生ビューの中身（背景、波形、バー、目盛りなど）。どちらのモードでも、色の設定で決めた色で描く
- アプリを使っている途中で、端末のモードが切り替わったときは、画面を作り直す
  - 音声データ、開始位置・終了位置、履歴、コピーバッファなどは、そのまま
  - 出ていたダイアログや設定画面は、閉じる。再生は、止まる。編集コマンドのグループの開く・畳むは、起動したときの状態（「ファイル」だけが開く）に戻る
  - 編集を実行している間に切り替わったときは、編集が終わってから作り直す
- アプリが自分で描く部品の色

| 部品 | ライトモード | ダークモード |
|---|---|---|
| スクロールバーの溝 | `#D0D0D0` | `#303030` |
| スクロールバーのつまみ | `#606060` | `#B0B0B0` |
| スクロールバーのつまみ（スクロールできないとき） | `#B0B0B0` | `#606060` |
| 縦の倍率バーの線 | `#909090` | `#808080` |
| 縦の倍率バーのつまみ | `#505050` | `#E0E0E0` |
| リピートがオンのときのボタン | `#81C784`（明るい緑） | `#2E7D32`（濃い緑） |

- ほかの部品の色は、Android の標準の配色（端末の色の設定に合わせた配色）による
- 文字の色
  - ラベル、項目名、見出し、データファイル名の表示など、ふつうの文字は、プライマリの文字色（標準の配色の、いちばんはっきりした文字色）で描く
  - Android の標準のままだと、見た目を指定しない文字は、目立たせない文字用の薄い色（セカンダリなど。一般には、無効な項目に使う色）になる。それを使わないよう、テーマで指定している
  - 使えない状態のボタンや入力欄は、標準のとおり、薄い色になる
- 以前は、ダークモードの配色だけだった

### 大きさ
最初の案。実装して確かめてから調整する。

| もの | 大きさ |
|---|---|
| 波形ビューの高さ | ほかのものを置いた残りの高さ（「編集画面の並び」の、大きさを決める順）。以前は、縦向きでは画面の高さの 1/2 としていた |
| 再生ビューの高さ | 24dp で固定（以前は、波形ビューの高さの 1/16） |
| 波形ビューの三角形の高さ | 波形ビューの高さの 1/24 |
| 再生ビューの三角形の高さ | 再生ビューの高さの 1/4 |
| バーをつかめる範囲（横） | 波形ビューの三角形の高さの 2 倍（バーの左右それぞれに、三角形の高さの分）。以前は半分の幅だったが、つかみにくいので倍にした |
| バーをつかめる範囲（縦） | バーいっぱい |
| 縦の倍率バーの幅 | 28dp |
| 再生・停止のボタンの幅 | 44dp。画面の横幅が 750dp 以上のときは、倍の 88dp（はじめは 600dp 以上としていた）。巻き戻し・リピートのボタンは、いつも 44dp |
| 波形ビュー・再生ビューの左の余白 | 縦の倍率バーの幅と同じ |
| 波形ビューの右の余白（縦の倍率バーとの間） | 縦の倍率バーの幅と同じ |
| 再生ビューの右の余白（再生のボタンとの間） | 縦の倍率バーの幅と同じ（仮） |

- バーをつかめる範囲（横）は、開始位置・終了位置のバーの左右それぞれに、波形ビューの三角形の高さの分。波形ビューでも再生ビューでも同じ
  - 再生ビューで再生位置をつかめる範囲は、広げていない（左右それぞれに、三角形の高さの半分）
- 波形ビューと再生ビューの左には、余白を置く。ビューの左端が画面の端に重なると、左端にあるバー（読み込んだ直後の開始位置など）を指でつかめないため
  - 余白には何も描かないが、触るとバーをつかめる。余白を触ったときは、描いている所の端を触ったものとして調べる。余白のどこを触っても、端にあるバー（端から、バーをつかめる範囲の中にあるバー）をつかめる
  - 再生ビューは、右（再生のボタンとの間）にも同じ余白がある。こちらも、触るとバーをつかめる
  - 再生ビューで余白を触ったときは、再生位置より先に、開始位置・終了位置のバーを調べる（余白でないときは、再生位置が先）。止まっているときの再生位置は開始位置と重なることが多く、再生位置を先にすると、左端の開始位置のバーをつかめないため
  - 波形ビューは、右（縦の倍率バーとの間）にも同じ余白がある。こちらも、触るとバーをつかめる
  - スクロールバーは、左端と右端を、波形（余白を除いた、描いている所）の左端と右端にそろえる
- 再生ビューの右端のボタンは、再生ビューより背が高い。行の高さはボタンに合い、再生ビューはその中で上下の中央に置く

### スクロールバー
- 縦にスクロールする所は、スクロールバーを常に表示する（スクロールが止まっても、消さない）
  - 中身が収まっていて、スクロールしないときは、バーは出ない
  - 対象：編集コマンドのボタン群（縦画面・横画面）、設定画面、カラーピッカー、アプリの情報、ライセンスの全文（横のスクロールバーも）、編集コマンドのダイアログ（音量の変更、音量の最大化、フェードイン・フェードアウト、音程の変更、サンプリングレートの変更、再生レートの変更、音のミックス・音の挿入・追加）、保存のパラメータのダイアログ、一覧から選ぶダイアログ（読み込むチャンネルの選択、モノラルにする方法）
- 編集コマンドのダイアログと、保存のパラメータのダイアログは、縦にスクロールできるようにした（以前は、スクロールせず、画面の高さが足りないと、下が切れていた）
- 進み具合のダイアログ（処理中、読み込み中、保存中）と、メッセージだけのダイアログは、対象にしていない

### チャンネルのスイッチ
- データファイル名の表示の右端に、「L」「R」の 2 つのスイッチ（押すたびにオン・オフが変わるボタン）を置く（ユーザーの指示）
  - オンのスイッチは、ボタンの背景の色で示す。L は、波形ビューの「ステレオの L だけの部分」の色、R は「ステレオの R だけの部分」の色（設定画面の「色の設定」で変えると、ボタンの色も変わる）
    - オンのときの文字の色は、背景の明るさに合わせて、黒か白にする（読みやすさのため）
    - 以前は、リピートのボタンと同じ緑だった
  - 起動したときは、両方オン。アプリを終了するまで覚える（音声ファイルを開き直しても、そのまま。保存はしない）
  - 押せるのは、ステレオの音声データを開いているときだけ。モノラルのとき・開いていないときは、押せない（色も付けない）。モノラルの音声データでは、スイッチに関係なく、その 1 つのチャンネルを加工する
- どちらか、または両方がオンの状態を保つ

| 今 | L を押す | R を押す |
|---|---|---|
| L=オン、R=オン | L=オフ、R=オン | L=オン、R=オフ |
| L=オン、R=オフ | L=オフ、R=オン（入れ替える） | L=オン、R=オン |
| L=オフ、R=オン | L=オン、R=オン | L=オン、R=オフ（入れ替える） |

- スイッチの意味 1：オフのチャンネルは、加工しない（元の音のまま）。音声データの長さが変わらない加工だけに効く

| 加工 | オフのチャンネルの扱い |
|---|---|
| 貼り付け | 元の音のまま。コピーバッファが末尾を越えて、音声データが伸びるときは、伸びた分は無音 |
| 音量の変更、無音化、フェードイン、フェードアウト、位相反転、逆再生 | 元の音のまま |
| 音量の最大化 | 元の音のまま。最大のレベルは、オンのチャンネルの中で調べる |
| 音のミックス | 元の音のまま（「元の音」の音量もかけない。足す音も足さない） |
| 音程の変更（「再生時間を維持する」がオンのとき） | 元の音のまま |

  - 長さが変わる加工（トリム、カット、挿入、音の挿入・追加、サンプリングレートの変更、「再生時間を維持する」がオフの音程の変更）と、チャンネル数の変更・再生レートの変更は、スイッチに関係なく、すべてのチャンネルが対象
  - コピーは、スイッチに関係なく、すべてのチャンネルを写す
  - チャンネル入れ替えは、長さが変わらない加工だが、スイッチに関係なく、常に L と R を入れ替える（ユーザーの指示）
- スイッチの意味 2：「無音区間を選択」「発音区間を選択」で、無音を検出するチャンネルを、オンのチャンネルに絞る
  - 例：L=オン、R=オフなら、L だけを見て無音かどうかを決める
- スイッチの意味 3：波形ビューに、オンのチャンネルだけを表示する（ユーザーの指示）
  - 両方オンのときは、以前のとおり、L と R を重ねて表示する
  - 片方だけオンのときは、そのチャンネルだけを表示する。色は、L は「ステレオの L だけの部分」、R は「ステレオの R だけの部分」の色
  - スイッチを押すと、すぐに表示が変わる
  - 再生ビューは、スイッチに関係なく、L と R を重ねて表示する（仮。ユーザーに確かめていない）
- スイッチの意味 4：再生で、オンのチャンネルだけを鳴らす（ユーザーの指示）
  - オフのチャンネルは、無音にして鳴らす（L だけなら、左からだけ聞こえる。L の音を右からも鳴らすことは、しない）（仮。ユーザーに確かめていない）
  - 再生中にスイッチを押すと、聞こえ方がすぐに変わる。ただし、出力にたまっている分（0.1 秒ほど）の後になる
  - モノラルの音声データは、スイッチに関係なく、そのまま鳴らす

### 波形ビュー
ビューの縦幅・横幅は固定。拡大しても、ビューの大きさは変わらない。

| | 縦 | 横 |
|---|---|---|
| 表すもの | サンプル値。0 を中心に上下に伸びる | 時間。左端を 0 として右に伸びる |
| 倍率を変える方法 | ビューの右の倍率バー | 指 2 本のピンチ（倍率バーはない。以前はビューの上にあったが、ピンチで変えられるようになったので、なくした） |
| 倍率の範囲 | 1 倍～256 倍 | 最小：音声データ全体がビューに収まる。最大：1 サンプルが 16px |
| 表示位置 | 拡大しても、中央は常に 0 | スクロールバーで動かす |
| スクロールバー | なし | あり |

- 縦を拡大してビューからはみ出した部分は、クリップする（ビューの上端・下端で切る）
- 目盛り：0 を示す水平線と、時刻を示す垂直線を描く。線の色は 3 段階（薄・中・濃）
  - 0 を示す水平線：ビューの上下の中央に、「濃」で描く
  - 時刻を示す垂直線
    - 単位は、1 時間、10 分、1 分、10 秒、1 秒、0.1 秒、0.01 秒…（1 秒より細かい単位は、1/10 ずつ）
    - 垂直線の間が 25dp 以上になる単位まで描く（それより細かい単位は描かない）
    - 色は、間が狭いほう（細かい単位）から「薄」「中」「濃」。それより粗い単位は、すべて「濃」
    - 1 つの時刻が、いくつもの単位にあたるとき（例：10 秒は、1 秒の単位でもある）は、いちばん粗い単位の色で描く
    - 描く位置は、その時刻と同じか、それを初めて越えたサンプルのピクセル。1 サンプルが 2px 以上になる倍率のときは、そのサンプルの左端のピクセル
    - 線の右、いちばん下に、時刻を表示する。いちばん細かい単位の線には、表示しない
    - ただし、波形ビューの横の中央にいちばん近い線には、いちばん細かい単位の線でも、必ず時刻を表示する。中央から同じ距離の線が 2 本あるときは、左の線だけに表示する
      - 中央は、端末の画面の中央ではなく、波形ビューの中央（波形を描いている所。左右の余白を除く）
  - 細かい決まり（仮。実装のときに決めた。ユーザーに確かめていない）
    - 線は波形の下に、時刻の表示は波形の上に描く。開始位置・終了位置のバーと再生位置は、どちらよりも上
    - 時刻の表示の形：1 時間以上は「時:分:秒」（例 `1:02:03`）、1 分以上は「分:秒」（例 `2:03`）、それより短いときは秒だけ（例 `3`）。小数は、その線の単位の桁まで（例 `1.25`）
    - 時刻の文字は、線の色に関わらず、「濃」の色で描く（ユーザーの指示）。文字の大きさは 10sp
    - 音声データの長さを越える時刻の線は、描かない。単位は、いちばん細かくて 0.000001 秒まで
    - 再生ビューには、目盛りを描かない
    - 3 つの色は、「色の設定」で変えられる
- 指 2 本の操作
  - 指 2 本でのスライド：左右にスクロールする
  - ピンチイン・ピンチアウト：横の倍率を変える。縦の倍率は変えない
  - 2 本の指の中点の下にある音声の位置が、指に付いて動く（スライドとピンチを同時にできる）
  - 倍率は、倍率の範囲（最小～最大）に収める。スクロールバーも、合わせて動く
  - 指の間隔は、横だけでなく、斜めの距離で測る（指を縦に並べて開いても、横の倍率が変わる）
  - 2 本目の指が触れたら、バーのドラッグはやめる。指が 1 本に戻っても、残った指では何もしない
- ダブルタップ：選択範囲の全体が、波形ビューの横幅いっぱいに表示される横の倍率にする
  - 表示の左端が開始位置、右端が終了位置になる
  - 選択範囲が短くて、最大の倍率（1 サンプルが 16px）でも横幅に足りないときは、最大の倍率にして、選択範囲を表示の中央に置く
  - 波形ビューのどこをダブルタップしてもよい。開始位置・終了位置は変えない
- ダブルタップ＆スライド（2 回目のタップで触れたまま、指を動かす）：横の動きで、横の倍率を変える
  - 右へ動かすと拡大、左へ動かすと縮小（仮）。96dp 動かすごとに、倍率が 2 倍（左なら半分）になる（仮）
  - 触れた所にあった音声の位置が、その場に残る（そこを中心に拡大・縮小する）
  - 縦の動きでは、何もしない
  - 倍率は、倍率の範囲（最小～最大）に収める。スクロールバーも、合わせて動く
  - 少しでも動かしたら（8dp 以上）、離したときに、ふつうのダブルタップ（選択範囲に合わせる）にはならない。縦に動かしただけでも同じ
  - この操作の間は、バーのドラッグや、縦のスワイプにはならない。開始位置・終了位置は変えない
- 指 1 本の縦のスワイプ（バーのない所から始める）

| スワイプ | 動き |
|---|---|
| 上から下 | 開始位置を、指を離した所へ動かす |
| 下から上 | 終了位置を、指を離した所へ動かす |

  - 開始位置が終了位置より左、という並びを保てない所へは、動かさない（どちらの位置も変えない）
    - 上から下で、離した所が終了位置より右（同じ位置も含む）のとき
    - 下から上で、離した所が開始位置より左（同じ位置も含む）のとき
  - 縦の動き（触れた所と離した所の、高さの差）が 48dp より短いときは、スワイプとみなさない（仮）。横にどれだけ動いたかは見ない
  - 開始位置・終了位置が実際に変わるのは、指を離したとき
  - スワイプの途中でも、スワイプとみなせる長さ（縦に 48dp 以上）になったら、バーを、指を離したらなる位置に表示する（指に付いて動く）。選択範囲の背景も、その位置で描く
    - このとき、開始位置・終了位置の数値の表示、再生ビュー、再生位置は、まだ変えない
    - 指の位置が、並びを保てない所（開始位置を、終了位置より右へ、など）にあるときは、バーを元の位置に表示する（離しても動かない所なので）
    - 触れた高さの近くへ指を戻して、スワイプとみなせない長さになったときも、バーを元の位置に表示する
  - バーをつかめる範囲から始めたときは、バーのドラッグになる。途中で 2 本目の指が触れたときは、指 2 本の操作になり、スワイプにはならない
  - 指 1 本の横のドラッグ（バーのない所）では、何も起きない
- 読み込んだ直後は、常に全体表示（横の倍率が最小）

背景の色。

| 部分 | 最初の色 |
|---|---|
| 開始位置と終了位置のバーの間（選択範囲） | グレー（`#404040`） |
| それ以外 | 黒（`#000000`） |

波形の色。

| 音声 | 部分 | 最初の色 |
|---|---|---|
| モノラル | すべて | やや輝度を下げた白 |
| ステレオ | L だけの部分 | 緑（`#00D800`） |
| ステレオ | R だけの部分 | 赤（`#FF2020`） |
| ステレオ | L と R が重なっている部分 | やや輝度を下げた白 |

- 「やや輝度を下げた白」は、`#CCC`（明るい灰色）くらい
- 波形の白は、開始位置・終了位置のバー（最大輝度の白）と見分けられるように、輝度をやや下げる

- 波形ビュー・再生ビューに描くものの色は、すべて色を設定するダイアログで利用者が変えられる（「色の設定」）。この文書に書いている色は、最初の色

- ステレオは、L と R を同じ位置に重ねて描く
- 読み込んだ直後の縦の倍率は 1 倍
- 縦の倍率バーは、位置に対して倍率が指数で変わる（等間隔に動かすと、同じ比率で拡大する）。下が 1 倍・上が 256 倍
- 横の倍率を変えるとき（ピンチ）は、2 本の指の中点の下にある位置を保つ（以前の横の倍率バーでは、表示の中央を保っていた）
- 全体表示でも 1 サンプルが 16px を越える短い音声は、横に拡大できない
- 1 サンプルが 1px より狭いときは、その列に入るサンプルの最小から最大までを縦線で描く。1px 以上のときは、サンプルの間を直線でつないだ形に描く
- 波形の縦線は、どんなに小さい音でも 1px は描く

### 開始位置・終了位置のバー
波形ビューの中に「開始位置」と「終了位置」の 2 つのバーがあり、音声データの操作位置を示す。2 つのバーの間を「選択範囲」と呼ぶ。

- 選択範囲は、背景をグレーにして示す（「波形ビュー」の背景の色）
- バーは、最大輝度の白の縦線。中央に三角形を描く

| バー | 三角形 | 三角形の位置 |
|---|---|---|
| 開始位置 | ▶ のような右向き | 三角形の左の縦の辺を、バーの縦線と同じ X 位置にする（三角形はバーの右側に出る） |
| 終了位置 | ◀ のような左向き | 三角形の右の縦の辺を、バーの縦線と同じ X 位置にする（三角形はバーの左側に出る） |

- 再生位置は、最大輝度の白の縦線だけで表す（三角形は付けない）
- 三角形の大きさと、バーをつかめる範囲は「大きさ」
- 再生ビューでも、同じ形で表す

- どちらもドラッグで動かせる
- 開始位置は、常に終了位置より左にある。ドラッグしても相手のバーは越えられない（終了位置も同じ）
- 2 つのバーの間は、最小で 1 サンプル分、最大で音声データ全体分
- 読み込んだ直後は、開始位置が左端（データの先頭）、終了位置が右端（データの末尾）
- 横に拡大したりスクロールしたりすると、バーがビューの表示範囲の外になることがある。そのバーは表示しない
  - バーが表示範囲の外でも、位置は変わらない。選択範囲の背景は、表示範囲に入っている分だけグレーになる

### 再生ビュー
波形ビューの下に置く。

| 項目 | 内容 |

| 縦の大きさ | 24dp で固定（「大きさ」） |
| 横の大きさ | 画面いっぱいの幅 |

ビューの右端に、次のボタンを並べる。

| 順 | ボタン | 動き |

| 2 | ■（停止） | 再生を停止する。指を離したときではなく、押したときに動く |

| 4 | ⟲（リピート） | 押すたびにオン・オフが切り替わる。オンのときは、繰り返し再生する。最初はオフ。オンのときは、ボタンを緑にして示す |

- 配色は、波形ビューと同じ（背景、選択範囲の背景、波形の色。「波形ビュー」）
- 開始位置・終了位置・再生位置の表し方も、波形ビューと同じ（「開始位置・終了位置のバー」）
- 開始位置・終了位置のバーをドラッグして、動かせる（波形ビューと同じ決まり）
  - 触った位置がどれに当たるかは、再生位置、開始位置・終了位置の順に調べる。再生位置とバーが重なっているときは、再生位置を動かす（シーク）
  - バーをつかめる範囲は「大きさ」
- 再生の動きは「再生」

#### ダイアログの値
- 編集コマンドのダイアログは、前回「OK」で実行したときの値を、次に開いたときの最初の値にする（ユーザーの指示）
  - 値を最初の値（各コマンドの節に書いた値）に戻すのは、アプリが起動したときだけ。アプリを終了するまで、覚えている（保存はしない）
  - 画面の向きを変えたり、音声ファイルを開き直したりしても、覚えている
  - 「キャンセル」で閉じたときは、覚えない（前回「OK」で実行したときの値のまま）
  - 「OK」を押して、値が変わらないため何もせずに終わったとき（音程差 0、今と同じサンプリングレートなど）も、覚える
  - コマンドごとに、別々に覚える（フェードインとフェードアウト、音のミックスと音の挿入・追加も、別）。変換方法だけは、サンプリングレートの変更・音程の変更・音のミックス・音の挿入・追加で共通（以前から）

| コマンド | 覚える値 |
|---|---|
| 音量の変更、音量の最大化、フェードイン、フェードアウト | 入れた dB の値（範囲の外の値は、範囲の端の値） |
| 音程の変更 | 音程差、「再生時間を維持する」、変換方法 |
| サンプリングレートの変更 | 変更後のサンプリングレート、変換方法 |
| 再生レートの変更 | 変更後の値 |
| チャンネル数の変更（ステレオからモノラル） | モノラルにする方法 |
| 音のミックス | 元の音の音量、音量、種類、周波数、繰り返し、変換方法、音声ファイル（場所と名前） |
| 音の挿入・追加 | 音量、長さ（決め方と秒数）、種類、周波数、繰り返し、変換方法、音声ファイル（場所と名前） |

  - サンプリングレートの変更・再生レートの変更：覚えた値が、一覧にないときは、今のサンプリングレートを選ぶ
  - 音のミックス・音の挿入・追加：今の種類で出ていない項目（無音のときの音量など）も、数値として正しければ覚える
  - 音のミックス・音の挿入・追加で選んだ音声ファイルは、場所（SAF の URI）と名前だけを覚える。中身は覚えない（ダイアログを閉じると捨てる）
    - 理由：中身をメモリに持ち続けると、編集中の音声データや、元に戻すための履歴に使えるメモリが、その分減る
    - 次にダイアログを開いたとき、種類が「音声ファイル」なら、すぐに読み直す（種類が違うときは、「音声ファイル」に変えたときに読み直す）。読み直す間は、「開く」と同じ、キャンセルのできる読み込みのダイアログを出す
    - 読み直せたら、ファイルの表示（名前と情報）と、変換方法の行（要るとき）が出る。中身は、読み直したときのもの（覚えた後にファイルが書き換えられていれば、書き換えた後の中身）
    - 読み直せなかったとき（消された、場所が変わったなど）は、「開く」と同じメッセージを出して、未選択に戻す。覚えた場所も忘れる。読み直しをキャンセルしたときも、同じく未選択に戻し、覚えた場所を忘れる
    - 選んだファイルを読む権限は、端末を再起動するまで続く（Android の決まり）。アプリを終了すると覚えた場所も忘れるので、権限を残す指定はしていない
    - 以前は、選んだ音声ファイルを、まったく覚えなかった
  - 保存のパラメータ（形式、量子化ビット数、ビットレート）は、以前から覚えている（「保存・名前を付けて保存・選択範囲を保存」）

#### 保存・名前を付けて保存・選択範囲を保存
- 保存
  - 「名前を付けて保存」を実行済みなら、そのときの設定（ファイル名とパラメータ）で、ダイアログを出さずに出力する
  - 実行済みでなければ、「名前を付けて保存」と同じ動き
- 名前を付けて保存：ダイアログでファイル名とファイル出力のパラメータを指定する
- 選択範囲を保存：出力するのは、開始位置から終了位置の間。ファイルに書き出すだけで、内部の音声データ・未保存の状態・データファイル名の表示は変えない
- 書き出しの後の置き換えを問うダイアログ（「機能」の書き出し）は、「保存」「名前を付けて保存」で出す。「選択範囲を保存」では出さない

ファイル出力のパラメータ。チャンネル数とサンプリングレートは選べない。内部の音声データのまま書き出す。選べる形式は、内部の音声データのサンプリングレートで決まる。

| 内部の音声データのサンプリングレート | 選べる形式 |
|---|---|
| 48kHz まで | wav・mp3・m4a |
| 48kHz を越える | wav・m4a |

- mp3 を選べるのは、48kHz までのうち、mp3 で書き出せる 9 つのサンプリングレート（8000・11025・12000・16000・22050・24000・32000・44100・48000Hz）のときだけ。ほかの値では、形式の選択肢に mp3 が出ない（仮。ユーザーに確かめていない）

- m4a は、音声だけが入った mp4 のファイル。圧縮は AAC
- mp3 の書き出しには、LAME 3.100（C のライブラリ。LGPL）を NDK で組み込んで使う。Android には mp3 のエンコーダーが標準で入っていないため
  - ビットレートは一定（CBR）。ステレオはジョイントステレオ、モノラルはモノラルで書き出す。LAME の品質の指定は 2（仮）
  - ファイルの先頭に、長さなどの情報のフレーム（LAME の Info タグ）を書く。読む側が、エンコードで前後に付く余分な無音を除けるようにするため
  - いったんアプリの作業用の場所に作ってから、保存先へ写す（m4a と同じ）

形式ごとに選ぶもの。

| 形式 | 選ぶもの |
|---|---|
| wav | 量子化ビット数（8 ビット・16 ビット） |
| mp3 | ビットレート |
| m4a | ビットレート |

- 保存の流れ
  - 「名前を付けて保存」「選択範囲を保存」は、まずパラメータのダイアログを出し、「OK」の後に Android 標準の保存先を選ぶ画面（SAF）を出す。ファイル名は、その画面で指定する。最初の名前は、データファイル名の拡張子を、選んだ形式のものに変えた名前
  - 保存先を選ばずに戻ったときは、何もしない
  - 書き出している間は、「保存しています…」のダイアログを出す（途中でやめることはできない）
  - 保存できなかったときは、「保存できませんでした。保存先を変えてもう一度お試しください。」を出す（文言は案）
- 「保存」が使う設定
  - 「名前を付けて保存」で保存できたときの保存先とパラメータを覚え、次の「保存」で使う（同じファイルに上書きする）
  - 別のファイルを読み込むと、覚えた保存先とパラメータは捨てる。その後の「保存」は、「名前を付けて保存」と同じ動きになる（仮）
  - 書き出した内容で置き換えた後は、覚えた保存先とパラメータを引き継ぐ（仮）
  - 「選択範囲を保存」の保存先は覚えない。パラメータのダイアログの最初の選択は、「名前を付けて保存」で最後に使ったものにする
- 「名前を付けて保存」で保存できたら、データファイル名の表示を、保存したファイルの名前にする（置き換えを選ばなくても。仮）
- パラメータの選択肢
  - 形式：選択肢の表示は「wav」「mp3」「m4a」。wav は常に選べる。m4a は、内部の音声データのサンプリングレートとチャンネル数で書き出せるエンコーダーが端末にあるときだけ選べる。48kHz を越えるかどうかでは分けていない（仮）
  - 量子化ビット数：16 ビット、8 ビット。最初の選択は 16 ビット
  - 形式：mp3 は、上の 9 つのサンプリングレートで、モノラルかステレオのときに選べる
  - ビットレート：64・96・128・160・192・256・320 kbps。最初の選択は 128 kbps（仮）
    - mp3 は、サンプリングレートが低いと上限が下がる（mp3 の規格による）。32000Hz 以上は 320 kbps まで、16000～24000Hz は 160 kbps まで、8000～12000Hz は 64 kbps だけ
    - 前に使ったビットレートが選べないときは、それより小さい中でいちばん大きい値を最初の選択にする
- m4a の書き出しには、Android 標準のエンコーダー（AAC-LC）を使う。いったんアプリの作業用の場所に作ってから、保存先へ写す
  - 書き出したファイルは、元の音声より少し長くなる（確かめた例では、4.0 秒が 4.063 秒）。AAC の仕組みによるもの
- wav の 8 ビットは、16 ビットの上位 8 ビットを使う（ディザはかけない）

#### 無音区間を選択・発音区間を選択
開始位置がその区間の中にあるとみなし、前後に区間を広げて、開始位置と終了位置で囲む。

- 無音：指定の期間の振幅（最大値と最小値の差）が、指定値以下である状態。区間の判定は、どちらもこの「無音」だけで決める
  - パラメータは 2 つ。期間の長さ（最初の値は 10 ミリ秒）と、振幅の指定値。どちらも設定画面で変えられる（「設定画面」）
  - 振幅の指定値は、設定画面では「無音の音量」として、dB で指定する（最初の値は -54.0dB。プリセットの「中」と同じ。振幅では約 131）
    - dB と振幅の関係：振幅 ＝ 65536 ÷ 10^(dB の大きさ ÷ 20)。0dB が、16bit の幅いっぱい（最大値と最小値の差が 65536）。-96dB で、振幅は約 1
  - 以前の定義は「サンプル値の微分値が指定値未満で、かつサンプル値が 0 付近」だった。ユーザーの指示で改めた

| 区間 | 範囲 |
|---|---|
| 無音区間 | 開始位置から左右に、無音が続いている範囲 |
| 発音区間 | 開始位置から左右に、無音になる点をそれぞれ探し、その 2 点の間 |

- 判定の細かい決まり（仮。実装のときに決めた。ユーザーに確かめていない）
  - 期間は、1 サンプルずつずらして、すべての位置で調べる。期間の長さは、サンプリングレート × ミリ秒 ÷ 1000 のサンプル数（1 サンプルより短くはしない。音声データより長いときは、音声データの長さ）
  - 無音区間は、無音の期間（振幅が指定値以下の期間）が、重なったり隣り合ったりして続いている範囲。その範囲のサンプルは、どれも、無音の期間のどれかに入っている
  - ステレオのときは、L と R の両方で振幅が指定値以下の期間だけを、無音とする
  - 振幅は、最大値と最小値の差なので、0 から離れた値（直流のずれ）で一定の音も、無音になる
  - 発音区間の範囲は、左右でいちばん近い無音の期間にはさまれた範囲。無音の期間が見つからない側は、音声データの端まで
- 区間の両端の位置（ユーザーの指示）：無音の期間が見つかったら、最終的な位置は、その期間の中から次の順で選ぶ
  1. 0 にいちばん近い位置（サンプル値の絶対値がいちばん小さい位置）
  2. それがいくつもあるときは、前後との差がいちばん小さい位置
  3. それもいくつもあるときは、無音が始まる側の端なら先頭に近い位置、無音が終わる側の端なら末尾に近い位置
     - 無音が始まる側の端：無音区間の開始位置、発音区間の終了位置
     - 無音が終わる側の端：無音区間の終了位置、発音区間の開始位置
     - はじめは、どちらも「先頭に近い位置」だった。値がすべて同じ無音（すべて 0 など）では、無音が終わる側の端が、音の始まりより期間の長さの分だけ手前になったので、ユーザーの指示で改めた
- 位置を選ぶ期間

| 区間 | 開始位置にする位置を選ぶ期間 | 終了位置にする位置を選ぶ期間 |
|---|---|---|
| 無音区間 | 続いている無音の期間のうち、いちばん左の期間 | いちばん右の期間 |
| 発音区間 | 左でいちばん近い無音の期間 | 右でいちばん近い無音の期間 |

  - 選び方の細かい決まり（仮。実装のときに決めた。ユーザーに確かめていない）
    - 「前後との差」は、1 つ前のサンプルとの差の絶対値と、1 つ後ろのサンプルとの差の絶対値を、足したもの。音声データの端では、ある側だけを使う
    - ステレオのときは、L と R の値を足して比べる（0 への近さも、前後との差も）
    - 無音区間で、無音が短くて、いちばん左の期間といちばん右の期間が同じ（または、選んだ位置が入れ違いになる）ときは、位置を選ばず、無音の期間の端そのままを区間にする
    - 発音区間の両端は、無音の期間の中の位置になるので、区間には、無音の部分が少し（期間の長さより短く）入ることがある
- 開始位置が、その区間の中にないとき（無音区間でない位置での「無音区間を選択」、無音区間の中での「発音区間を選択」）は、選択範囲を変えずに、メッセージを出す（文言は案）
  - 「開始位置が無音区間にありません。開始位置を無音の所へ動かしてください。」
  - 「開始位置が発音区間にありません。開始位置を音のある所へ動かしてください。」
- 音声データは変えない。未保存にはならず、元に戻す・やり直すの対象でもない
- 探すのは、画面とは別のスレッドで行う。時間がかかるときは、ほかの編集と同じく、進み具合とキャンセルのダイアログを出す

#### トリム・カット・コピー・貼り付け・挿入
- トリム：開始位置より左のデータと、終了位置より右のデータを捨てて、選択範囲だけを残す。音声データは、選択範囲の長さになる
  - コピーバッファは変えない（捨てたデータは、コピーバッファに入らない）
  - 実行の後は、残った音声データの全体が、選択範囲になる（仮）
  - 音声データの全体を選んでいるときは、捨てる所がないので、何もしない（メッセージも出さない。未保存にもならない。仮）
  - 元に戻す・やり直すの対象。ダイアログは出さず、すぐに実行する
- コピーバッファ：カット・コピーで選択範囲の音声を入れておく場所
- カット：音声データは、選択範囲の分だけ短くなる
- 貼り付け：開始位置から、コピーバッファの長さの分を上書きする。データの末尾を越えるときは、音声データを伸ばしてから貼り付ける
- 挿入：開始位置にコピーバッファの内容を割り込ませる。音声データは、コピーバッファの長さの分だけ長くなる
- 末尾に追加：コピーバッファの内容を、音声データの末尾につなげる。開始位置・終了位置には関係しない（ユーザーの指示）。L・R のスイッチにも関係しない（長さが変わるため）
- 貼り付け・挿入・末尾に追加で長さの上限を越える分は、末尾を切り捨てて警告を出す（「音声データの長さの上限」）
- 実行の後の開始位置・終了位置（仮）

| コマンド | 実行の後の選択範囲 |
|---|---|
| トリム | 残った音声データの全体 |
| カット | つないだ位置から 1 サンプル分 |
| コピー | 変わらない |
| 貼り付け・挿入・末尾に追加 | 貼り付けた・挿入した・追加した範囲 |

- 音声データ全体を選んでいるときは、カットできない。「音声データ全体はカットできません。」を出す（音声データを空にはできないため。文言は案）
- コピーバッファが空のときは、「貼り付け」「挿入」「末尾に追加」を押せなくする
- コピーバッファと音声データでチャンネル数が違うときは、貼り付け・挿入・末尾に追加のときに音声データのチャンネル数に合わせる。モノラルからステレオは L と R に同じ音を入れ、ステレオからモノラルは足して 2 で割る（仮）
- サンプリングレートが違っても、変換せずにサンプルをそのまま貼り付ける（仮）
- 別のファイルを読み込んでも、コピーバッファは残す。別のファイルへ貼り付けられる（仮）
- コピーバッファは、元に戻す・やり直すの対象ではない

「選択範囲の加工」のボタン。どれも選択範囲の音量を変える。

| 順 | ボタン | 動き |
|---|---|---|
| 1 | 音量の変更 | ダイアログで指定した倍率で、音量を変える |
| 2 | 音量の最大化 | 選択範囲の最大のレベルを調べ、それがダイアログで指定したレベルになるように音量を変える |
| 3 | 無音化 | 音量を 0 にする |
| 4 | フェードイン | 開始位置を指定のレベル、終了位置を 0dB として、音量を上げていく |
| 5 | フェードアウト | 開始位置を 0dB、終了位置を指定のレベルとして、音量を下げていく |

#### 音量の変更・音量の最大化
どちらも、ダイアログで値を dB で指定して実行する。単位は dB だけ（以前は % と dB を切り替えられた。ユーザーの指示で、dB だけにした）。

| コマンド | 指定する値 | 範囲 |
|---|---|---|
| 音量の変更 | 音量をどれだけ変えるか（0dB で変わらない。+6dB で約 2 倍、-6dB で約半分） | -48～+48dB |
| 音量の最大化 | 最大のレベルからどれだけ下げるか（0dB で最大） | -96～0dB |

- ダイアログには、数値の入力欄と、その下にスライダーがある
  - 部品の並び（音量を入れる部品。dB で音量・レベルを入れる所は、どれもこの並び：音量の変更、音量の最大化、フェードイン・フェードアウト、音のミックス・音の挿入・追加、設定画面の「無音の音量」）

| 行 | 左から |
|---|---|
| 1 | 項目名（例「最大のレベル」）、数値の入力欄（数値は右寄せ）、単位「dB」 |
| 2 | 範囲の小さい側の値（例「-96」）、スライダー、範囲の大きい側の値（例「0」） |

    - 例：`最大のレベル [   -96] dB` の下に、`-96 [スライダー] 0`
    - 2 行目は、1 行目の「入力欄＋単位」の真下に置き、「範囲の値＋スライダー」の幅を、「入力欄＋単位」の幅と同じにする。項目名の下は、空ける
    - 項目名には、単位や範囲を書かない（単位と範囲は、右と下のラベルで示す）
    - 以前は、「音量（dB、-48～48）」のような項目名の下に、入力欄、その下にスライダーを、ダイアログの幅いっぱいに並べていた
    - 「音程の変更」の音程差も、同じ並び（単位は「半音」）
  - 数値の入力欄は、小数も受け付ける（例 `-6.5`）
  - スライダーは 1dB きざみ。スライダーから入れた値は、小数点以下が常に 0 になる
  - スライダーを動かすと、数値の入力欄がその値になる。数値を入力すると、スライダーのつまみがその値の位置（小数は、近い整数の位置）に動く
- ダイアログの最初の値は、どちらも 0（仮）。小数は 4 桁まで表示する
- 範囲の外の値を入力して「OK」を押したときは、範囲の端の値で実行する（仮）
- 音量の最大化は、先に選択範囲の音量のレベルを調べてから実行する
  - 0dB のとき、選択範囲の最大のレベルが、16bit で表せる最大になる
  - ステレオのときは、L と R のうち最大のレベルが大きいほうに合わせる。L と R の音量は、同じ倍率で変える
  - 選択範囲がすべて無音のときは、何もせずに終わる。メッセージは出さない
- 変更の後のサンプル値が 16bit の範囲を越えるときは、範囲の端にクリップする
- 音量の変更では、音量を 0 にはできない（いちばん下げて -48dB）。0 にするには、「無音化」を使う

#### フェードイン・フェードアウト
ダイアログでレベルを 0～-96dB で指定して実行する。

| コマンド | 開始位置のレベル | 終了位置のレベル |
|---|---|---|
| フェードイン | 指定のレベル | 0dB |
| フェードアウト | 0dB | 指定のレベル |

- 音量の時間変化は、リニアではなく対数にする（dB の値が、時間に対してまっすぐ変わる）
- ダイアログの最初の値は -96。小数でも指定できる（仮）
- ダイアログには、数値の入力欄の下に、スライダーがある。作りは、「音量の変更・音量の最大化」と同じ（範囲は -96～0dB、1dB きざみ。スライダーから入れた値は、小数点以下が常に 0）
- 無音化は、ダイアログを出さずにすぐ実行する
- 位相反転：選択範囲のサンプルの符号を反転する（v を -v にする）。16bit では -32768 の反転が表せないので、32767 にする。ダイアログを出さずにすぐ実行する
- 逆再生：選択範囲のサンプルの並びを、時間の向きに反転する（選択範囲の先頭と末尾を入れ替える）。ステレオは、L と R を、それぞれ反転する。ダイアログを出さずにすぐ実行する
- チャンネル入れ替え：選択範囲の L と R を入れ替える。ダイアログを出さずにすぐ実行する。L・R のスイッチに関係なく、常に両方を入れ替える（ユーザーの指示）。モノラルの音声データを開いているときは、ボタンを押せない
- 位相反転・逆再生・チャンネル入れ替えの後も、選択範囲は変わらない。元に戻せる。進み具合の表示とキャンセルは、ほかの編集と同じ

「全体の加工」のボタン。どれも音声データ全体が対象で、選択範囲には関係しない。

| 順 | ボタン | 音程 | サンプリングレート | サンプルのデータ |
|---|---|---|---|---|
| 1 | 音程の変更 | 変える | 変えない | 変える |
| 2 | サンプリングレートの変更 | 変えない | 変える | 変える |
| 3 | 再生レートの変更 | 変わる | 変える | 変えない |
| 4 | チャンネル数の変更 | 変えない | 変えない | 変える（チャンネル数が変わる） |

#### 音程の変更・サンプリングレートの変更・再生レートの変更
どれもダイアログで値を指定して実行する。

| コマンド | 指定する値 | サンプリングレート変換アルゴリズム |
|---|---|---|
| 音程の変更 | -24～+24（小数で指定できる）。1 で平均律の半音、12 で 1 オクターブ。以前の範囲は -96～+96 | ドロップダウンで選ぶ |
| サンプリングレートの変更 | 変更後のサンプリングレート。ドロップダウンで選ぶ | ドロップダウンで選ぶ |
| 再生レートの変更 | 変更後の再生レート。ドロップダウンで選ぶ | 使わない |

- サンプリングレート・再生レートのドロップダウンに出すのは、1000～192000Hz のうち、再生するハードウェアで指定できる値
- 「サンプリングレートの変更」「再生レートの変更」のダイアログには、現在のサンプリングレートも表示する（「再生レートの変更」では、「現在の再生レート」と表示する）
- 再生レートの変更は、サンプルのデータを変えずに、サンプリングレートの値だけを変える。音程と長さ（秒）が変わる
- 音程の変更のダイアログには、「再生時間を維持する」スイッチがある

| 「再生時間を維持する」 | 動き | 音声の長さ |
|---|---|---|
| オン | タイムストレッチを行う | 変わらない |
| オフ（最初の状態） | タイムストレッチを行わない | 変わる（音程を上げると短く、下げると長くなる。-24 では 4 倍、+24 では 1/4） |

- タイムストレッチの方式は WSOLA（波形の似た所を探して、短い区間を重ねながらつなぐ方式）。タイムストレッチとサンプリングレート変換を組み合わせて、長さを変えずに音程を変える
  - 順は、短くするほうを先にする。音程を上げるときは、サンプリングレート変換で短くしてから、タイムストレッチで元の長さに戻す。音程を下げるときは、タイムストレッチで短くしてから、サンプリングレート変換で元の長さに戻す
    - 途中のデータが元より長くならないようにするため（先に伸ばすと、+24 では 4 倍の長さのデータが要る）
  - 音程を大きく変えるほど、音の劣化が大きくなる
  - WSOLA の値（仮。音を聞いて確かめていない）：つなぐ区間は約 30 ミリ秒で、半分（約 15 ミリ秒）ずつ重ねる。似た所を探す範囲は、前後に約 12 ミリ秒。探すのは、チャンネルを混ぜた信号で行い、L と R は同じ位置でつなぐ

サンプリングレート変換アルゴリズム（ドロップダウンの並び順）。最初の選択は「窓関数付き sinc（標準）」。

| アルゴリズム | 品質 | 速さ | 内容 |
|---|---|---|---|
| 最近傍 | 低い | 最も速い | いちばん近いサンプルをそのまま使う |
| 線形補間 | やや低い | 速い | 隣り合う 2 サンプルを直線で結ぶ |
| 3 次補間（Catmull-Rom） | 中 | やや速い | 前後 4 サンプルで曲線を引く |
| 窓関数付き sinc（標準） | 高い | 遅い | 窓関数で有限の長さに切った sinc で補間する。レートを下げるときは遮断周波数を下げて、折り返しの雑音を防ぐ |
| 窓関数付き sinc（高品質） | 最も高い | 最も遅い | 上と同じ方式で、使うサンプル数を増やしたもの |

- 最近傍・線形補間・3 次補間は、レートを下げるとき（音程を上げるときも同じ）に折り返しの雑音が残る
- 窓関数付き sinc の窓関数は、カイザー窓。値は最初の案で、実装して音を確かめてから調整する
  - 遮断周波数は、低いほうのサンプリングレートの半分（ナイキスト周波数）に対して、標準が 0.90 倍、高品質が 0.96 倍（仮）。窓が短いほど、なだらかに落ちるので、手前に置く

| | 使うサンプル数 | 阻止域の減衰量 | カイザー窓の β |
|---|---|---|---|
| 標準 | 片側 16（計 32） | 80dB | 約 7.86 |
| 高品質 | 片側 64（計 128） | 100dB | 約 10.06 |

長さの上限。

- 変更の後の長さは、パラメータから実行の前に求められる。ダイアログに、変更の後の長さが上限（「音声データの長さの上限」）を越えるかどうかを、あらかじめ表示する
  - 再生レートを下げると、サンプル数は同じでも秒数が増える。これも対象
- 越えると表示されたまま実行したときは、末尾を切り捨て、実行の後にも警告を出す（「音声データの長さの上限」）

再生するハードウェアで指定できる値。

- システムから取得できれば、その値を使う
- 取得できなければ、起動時に決め打ちの値（48kHz 系、44.1kHz 系、32kHz 系）を総当たりで試して、使える値を調べる
  - 試す値の案：48kHz 系（192000・96000・48000・24000・12000・6000・3000・1500）、44.1kHz 系（176400・88200・44100・22050・11025）、32kHz 系（128000・64000・32000・16000・8000・4000・2000・1000）

変更の後の開始位置・終了位置。

- 音声データの長さ（サンプル数）が変わらないときは、元のまま
- 変わるときは、伸び縮みに合わせた位置にする（音声の同じ所を指す位置）

- 再生するハードウェアで指定できる値は、今は総当たりだけで調べている（システムからの取得は未実装）。最初に必要になったときに、次の 21 個を試す：1000・1500・2000・3000・4000・6000・8000・11025・12000・16000・22050・24000・32000・44100・48000・64000・88200・96000・128000・176400・192000
  - 確かめた実機（Pixel 7a）では、1000・1500・2000・3000 が使えず、4000 以上の 17 個が使えた
- 「再生レートの変更」のダイアログ
  - 最初の選択は、現在のサンプリングレート（一覧にあるとき）
  - 並び：1 行目に「現在の再生レート：48000 Hz」、2 行目に、左に項目名「変更後」、右にドロップダウン（「サンプリングレートの変更」と同じ形）

```
現在の再生レート：48000 Hz
変更後 [44100 Hz              ▼]
```

  - 以前は、「現在のサンプリングレート：48000 Hz」の下に、項目名なしで、ドロップダウンを置いていた
  - 上限を越えるときは、「データが長すぎます。末尾データをカットします。」をダイアログの中に表示する
  - 現在と同じ値を選んで「OK」を押したときは、何もせずに終わる
- 「サンプリングレートの変更」のダイアログ
  - 現在のサンプリングレート、変更後のサンプリングレート（ドロップダウン。最初の選択は現在の値）、変換アルゴリズム（ドロップダウン）
    - 「変更後」と「変換方法」は、それぞれ 1 行に、左に項目名、右にドロップダウンを置く。2 つの項目名の幅をそろえて、ドロップダウンの左端を合わせる

```
現在のサンプリングレート：44100 Hz
変更後   [44100 Hz              ▼]
変換方法 [窓関数付き sinc（標準）▼]
```

    - 以前は、項目名「変更後のサンプリングレート」の下に、ドロップダウンを置いていた
  - 現在と同じ値を選んで「OK」を押したときは、何もせずに終わる
- 「音程の変更」のダイアログ
  - 上から、音程差（数値の入力欄とスライダー。最初の値は 0）、説明「（12 で 1 オクターブ）」、変換方法（ドロップダウン）、「再生時間を維持する」スイッチ

```
音程差   [            0] 半音
         -24 [スライダー] 24
                （12 で 1 オクターブ）

変換方法 [窓関数付き sinc（標準）▼]
再生時間を維持する      （スイッチ）
```

  - 音程差の所は、「音量を入れる部品」と同じ並び（左に項目名、右に入力欄と単位「半音」、その下に、範囲の値「-24」「24」とスライダー）
  - 説明「（12 で 1 オクターブ）」は、スライダーの下に、右寄せで出す
  - 「音程差」と「変換方法」の項目名の幅をそろえて、入力する所の左端を合わせる
  - 以前は、項目名「音程（-24～24。1 で半音、12 で 1 オクターブ）」の下に、入力欄、スライダー、「再生時間を維持する」スイッチ、変換アルゴリズムの順に並べていた
  - 音程差の入力の動きは、「音量の変更・音量の最大化」のダイアログと同じ。数値の入力欄は、小数も受け付ける（例 `-0.5`）。スライダーは 1 きざみ（半音ごと）で、スライダーから入れた値は、小数点以下が常に 0 になる
  - 範囲の外の値は、範囲の端の値で実行する。0 のときは、何もせずに終わる
- 変換アルゴリズムを選ぶ所は、1 行に、左に項目名「変換方法」、右にドロップダウンを置く（「音のミックス・音の挿入・追加」のダイアログと同じ形）
  - 画面での項目名は、「変換方法」。以前は、項目名「変換アルゴリズム」の下に、ドロップダウンを置いていた
- 変換アルゴリズムの最初の選択は「窓関数付き sinc（標準）」。一度選ぶと、アプリを終了するまで、次のダイアログの最初の選択になる（仮）
- 上限を越えるときの表示は、「再生レートの変更」と同じ
- 変更の後の長さ（サンプル数）は、元の長さ × 変更後のレート ÷ 元のレート（音程の変更では、元の長さ ÷ 周波数の比）を、近いほうの整数に丸める。開始位置・終了位置も、同じ比で近いほうに丸める（仮）

#### 音のミックス・音の挿入・追加
「音の追加」のボタン。ほかの音（波形、音声ファイル）を、音声データに足す。

| ボタン | 動作 | 実行の後の選択範囲 |

| 音の挿入・追加 | 開始位置に、ほかの音を割り込ませる。開始位置より後ろは、その分だけ後ろへずれる。終了位置は関係しない。または、音声データの末尾につなげる（ダイアログのボタンで選ぶ） | 入れた音の全体 |

- ダイアログで、足す音の種類を、ドロップダウンで選ぶ。選んだ種類に合わせて、要る項目だけを表示する

| 種類 | 音のミックス | 音の挿入・追加 |
|---|---|---|
| 無音 | 選べない | 選べる（最初の選択） |
| サイン波 | 選べる（最初の選択） | 選べる |
| 矩形波 | 選べる | 選べる |
| 音声ファイル | 選べる | 選べる |

- ダイアログの項目（項目の中身。並びは、この表の後の「音のミックスの並び」「音の挿入・追加の並び」）

| 項目 | 出る場合 | 内容 |
|---|---|---|
| 「元の音」の「音量」 | 音のミックス | 元の音（選択範囲の、今ある音）の音量。dB。-96～0、最初の値は 0 |
| 「種類」 | いつも | 足す音の種類 |
| 「周波数」 | サイン波・矩形波 | Hz。0 以上（上限なし）、小数でも指定できる。最初の値は 1000 |
| 選んだファイルの表示と、「開く」ボタン | 音声ファイル | 1 行に並べる。下の「音声ファイル」 |
| 「変換方法」 | 音声ファイルで、サンプリングレートの変換が要るとき | 「サンプリングレートの変更」と同じドロップダウン。最初の選択も同じ（最後に選んだもの） |
| 「音量」 | 無音のほか | 足す音の音量。dB。-96～0、最初の値は 0 |
| 「長さ」（ドロップダウン） | 音の挿入・追加で、音声ファイル | 「ファイル全体」（最初の選択）か、「長さを指定」 |

  - 種類が「無音」のときは、「長さ」と「種類」だけ（「音量」は出ない）
  - 種類が「音声ファイル」のときは、次のとおり。「長さ」は、ドロップダウン（「ファイル全体」「長さを指定」）で、「長さを指定」のときだけ、その下に、秒数の行（項目名は空ける）が出て、いちばん下に「繰り返し」が出る

         -96 [スライダー] 0

  - 種類を変えると、その上の項目（音量、長さ）の行の数が変わるので、「種類」の位置が上下に動く
  - 以前は、「挿入する音」（種類のドロップダウン）、周波数、ファイルの表示と「開く」、変換アルゴリズム、音量、挿入する長さ、長さ、繰り返しの順に、項目名の下に入力する所を並べていた
- 音量（dB）の入力欄は、小数も受け付け、下にスライダー（1dB きざみ）がある。作りは、「音量の変更・音量の最大化」と同じ。範囲の外の値は、範囲の端の値で実行する
- ダイアログのボタン
  - 音のミックス：「キャンセル」「OK」
  - 音の挿入・追加：左から「キャンセル」「開始位置に挿入」「末尾に追加」（ユーザーの指示）。「開始位置に挿入」は開始位置に割り込ませ、「末尾に追加」は音声データの末尾につなげる。どちらも、入れた音を選択範囲にする
    - 以前は、「キャンセル」「OK」（開始位置に挿入）だった
    - Android 標準のダイアログのボタンの並び（左から neutral、negative、positive）に当てているので、「キャンセル」は左端に離れて、「開始位置に挿入」「末尾に追加」は右に並ぶ
- 実行のボタンを押したときに、入力に誤りがあれば、メッセージを出して、ダイアログは開いたままにする（入れた値は残る）

| 誤り | メッセージ |
|---|---|
| 音量が、数値でない | 「音量が正しくありません。」 |
| 周波数が、数値でない・負 | 「周波数が正しくありません。」 |
| 長さが、数値でない・0 以下・1 サンプルに満たない | 「長さが正しくありません。」 |
| 長さが、挿入の後の全体の長さの上限（「音声データの長さの上限」）を越える | 「長さが上限を超えています。（入る長さ）秒以下で指定してください。」。入る長さは、小数 3 桁で、切り捨てて示す |
| 音声ファイルを選んでいない | 「音声ファイルを選択してください。」 |

- 音声データの長さが、すでに上限いっぱいのときは、「音の挿入・追加」のダイアログを出さずに、「音声データの長さが上限に達しているため挿入できません。」と表示する
- 16bit の範囲を越える値は、クリップする（混ぜた結果、音量をかけた結果）
- どちらも、画面とは別のスレッドで実行し、進み具合の表示とキャンセルができる（「トリム・カット・コピー・貼り付け・挿入」などと同じ）。元に戻せる
- コピーバッファは、使わないし、変えない

サイン波・矩形波

- 振幅は、音量が 0dB のとき 32767。L と R に、同じ波形を入れる
- 波は、足す範囲の先頭（音のミックスでは開始位置、音の挿入・追加では挿入した音の先頭）から始まる（位相 0）
- サイン波は、0 から始まり、正の側へ上がる
- 矩形波は、1 周期の前半が正の値、後半が負の値。帯域を制限していない（高い周波数では、折り返しの音が混じる）
- 周波数が、サンプリングレートの半分より高いときも、そのまま計算する（折り返した音になる）
- 周波数が 0 のとき、サイン波は無音になり、矩形波は正の値のままになる

音声ファイル

- 選んだファイルの表示と、その右の「開く」ボタンを、1 行に並べる
  - ファイルの表示は、編集画面のデータファイル名と同じ作り（編集はできない入力欄。1 行で、長いときは、横にスクロールして全体を見られる）
  - 表示の形も同じで、`ファイル名 [44.1kHz/2ch/4.00000秒/176400サンプル]`。選ぶ前は「（ファイルを選択していません）」
  - 以前は、「ファイルを選択」ボタン、ファイル名、ファイルの情報を、3 行に分けていた
- 「開く」を押すと、ファイルを選ぶ画面（SAF。編集コマンドの「開く」と同じ）が出る。選ぶと、そのときに読み込む（読み込みの間は、「開く」と同じ、キャンセルのできるダイアログを出す）
  - 読み込めなかったときのメッセージは、「開く」と同じ
  - 読める形式・長さの上限は、「扱う音声ファイル」と同じ（長さの上限を越える分は、黙って使わない）
  - 3ch 以上のファイルは、使えない。「チャンネル数が 3 以上のファイルは使用できません。モノラルかステレオのファイルを選択してください。」と表示する（「開く」のような、チャンネルを選ぶ画面は出さない）
  - 選んだファイルは、ダイアログを閉じると忘れる（次に開いたときは、選び直す）
  - 編集中の音声データ・ファイル名・未保存の印は、変わらない
- サンプリングレートが、編集中の音声データと違うときは、選んだ変換アルゴリズムで、音声データのサンプリングレートに変換する（音程と長さ（秒）は変わらない）
- チャンネル数が、編集中の音声データと違うときは、自動で合わせる

| ファイル | 音声データ | 変換 |
|---|---|---|
| モノラル | ステレオ | L と R に、同じ音を入れる |
| ステレオ | モノラル | L と R の平均（足して 2 で割る） |

- 音のミックス：ファイルの先頭を、開始位置に合わせて混ぜる
  - ファイルが選択範囲より長いとき：選択範囲の長さまでを使う
  - ファイルが選択範囲より短いとき：「繰り返し」がオンなら、ファイルを先頭から繰り返して混ぜる。オフなら、ファイルが終わった後には何も足さない（「元の音の音量」は、選択範囲の全体にかかる）
- 音の挿入・追加で「ファイル全体」：ファイルの全体を挿入する
  - 挿入の後の長さが上限を越えるときは、入る分だけを挿入して（ファイルの末尾を切り捨てる）、「データが長すぎます。末尾データをカットします。」のメッセージを出す。元の音声データは、切り捨てない
- 音の挿入・追加で「長さを指定」：指定の長さの無音を挿入して、その先頭からを、ファイルの内容で置き換える
  - ファイルが指定の長さより長いとき：指定の長さまでを使う
  - ファイルが指定の長さより短いとき：「繰り返し」がオンなら、ファイルを先頭から繰り返す。オフなら、残りは無音のまま

### 設定画面
メニューの「設定」で開く。アプリの設定を変える。

| 設定 | 内容 |
|---|---|
| 色の設定 | 波形ビュー・再生ビューに描くものの色（「色の設定」） |
| 無音の判定 | 無音の判定に使う設定値（期間の長さ、振幅の指定値。「無音区間を選択・発音区間を選択」） |
| 元に戻す | 元に戻せる最大回数。0～99、最初の値は 10（「元に戻す」） |

- 「色の設定」「無音の判定」のそれぞれに、「初期値に戻す」ボタンを置く。押すと、そのまとまりの設定をすべて最初の値に戻す。確認はしない
- 設定を変えると、すぐに反映する（保存や適用のボタンは置かない）
- 設定は、Android の SharedPreferences に保存する（名前は `settings`）。起動のときに読み込む
- 画面の作り
  - 画面全体を使う。上に「設定」の見出しと「閉じる」ボタン、その下に、設定のまとまりを縦に並べる（縦にスクロールする）。戻るボタンでも閉じる
  - 設定画面を開くと、再生は停止する
- 設定の表示の名前と範囲（名前は案）

| まとまり | 表示の名前 | 範囲 | 最初の値 |
|---|---|---|---|
| 無音の判定 | 判定する期間の長さ（ミリ秒） | 1～1000 | 10 |
| 無音の判定 | 無音の音量 | -96～0dB（小数も指定できる） | -54dB（「中」と同じ） |
| 元に戻す | 元に戻せる最大回数 | 0～99 | 10 |

  - 「無音の音量」は、数値の入力欄と、その下のスライダーで指定する。作りは、「音量の変更・音量の最大化」のダイアログと同じ
    - 数値の入力欄は、小数も受け付ける（例 `-50.5`）。入力を終えたときに反映する（ほかの数値の設定と同じ）
    - スライダーは 1dB きざみ。左が小さい音（-96dB）、右が大きい音（0dB）。スライダーから入れた値は、小数点以下が常に 0 になる
    - 値は、最大の音量からどれだけ下かなので、マイナスの dB で表す（ユーザーの最初の指示は「0～96」。表示にマイナスを付けたのは私の判断で、ユーザーに確かめていない）
    - 以前は、0.1dB きざみのスライダーだけで、数値の入力欄はなかった
  - 「無音の音量」には、プリセットのボタンがある。押すと、入力欄とスライダーがその値になる。並びは、左から「小」「中」「大」（スライダーの向きと同じ。はじめは「大」「中」「小」の順だった）

| ボタン | 値 | 振幅 |
|---|---|---|
| 小 | -66dB | 約 32（計算では 33） |
| 中（最初の値） | -54dB | 約 128（計算では 131） |
| 大 | -42dB | 約 512（計算では 521） |

  - 無音の判定の「初期値に戻す」は、期間の長さを 10 ミリ秒、無音の音量を -54.0dB に戻す
- 数値の入力欄の設定は、入力を終えたときに反映する。入力を終えたとき、とは、キーボードの確定のキーを押したとき、ほかの所へ移ったとき、設定画面を閉じたとき
  - 入力の途中の値は、反映しない（「-120」と打つ途中の「-12」が、設定になってしまうのを防ぐため）
  - 範囲の外の値や、空のまま入力を終えたときは、今の設定の値に戻す
  - スライダー、プリセットのボタン、カラーピッカー、「初期値に戻す」は、操作したときに、すぐに反映する
- 元に戻せる最大回数を減らしたときは、越えた分の履歴を、その場で古いものから捨てる

### 色の設定
設定画面の中にある。波形ビュー・再生ビューに描くものの色を、利用者が変えられる。2 つのビューの配色は同じで、設定も共通。

| 設定できる色 | 最初の色 |
|---|---|
| 背景 | 黒 |
| 選択範囲の背景 | グレー |
| モノラルの波形 | やや輝度を下げた白 |
| ステレオの L だけの部分 | 緑 |
| ステレオの R だけの部分 | 赤 |
| ステレオの L と R が重なっている部分 | やや輝度を下げた白 |
| 開始位置のバー（三角形も） | 最大輝度の白 |
| 終了位置のバー（三角形も） | 最大輝度の白 |
| 再生位置 | 最大輝度の白 |
| 目盛りの線（薄） | R・G・B は `#7FFFFF`（明るい水色）、A（不透明度）は 64 |
| 目盛りの線（中） | R・G・B は `#7FFFFF`、A は 160 |
| 目盛りの線（濃） | R・G・B は `#7FFFFF`、A は 224。0 を示す水平線と、時刻の文字も、この色 |

- 目盛りの線の 3 つの色は、色あいが同じで、不透明度だけが違う。半透明なので、下にある背景や選択範囲の背景の色が透けて見える
- 設定を保存するとき、最初の色のままの色は、保存しない（最初の色を後で変えたときに、新しい色になるようにするため）。変えた色だけを保存する
- 最初の色に戻すには、設定画面の「初期値に戻す」ボタンを使う。色をまとめて戻す（「設定画面」）
- 設定画面には、色ごとに、名前と色の見本を 1 行で表示する。行を押すと、カラーピッカーが開く
- 色は、アプリが用意する簡単なカラーピッカーで選ぶ。Android に標準の色を選ぶ UI がないため
  - R・G・B・A の 4 つの値を、それぞれスライダーと数値（0～255）で入力する
  - 選んでいる色を、サンプルとして表示する
  - スライダーを動かしたり、数値を入れたりするたびに、すぐに反映して保存する。カラーピッカーのボタンは「閉じる」だけで、取りやめはできない（仮）

## アプリ名・バージョン（Profile.ini）
リポジトリ直下の `Profile.ini` に、アプリ名などの定数がある。著作者だけが書き換え、プログラムからは読むだけ。

- ビルドのとき、`app/build.gradle` が `Profile.ini` を読み、アプリ ID・バージョン・アプリの表示名と、コードから使う定数（`BuildConfig` の `PROFILE_…`）にする
- コードからは、`AppProfile`（`AppProfile.SHORT_TITLE` など）を使う。`AppProfile` は `BuildConfig` の値を名前を付けて並べただけのクラス
- 必要な値（[Title] Text・ShortText、[Version] Text・Number、[Copyright] Text、[AppId] Namespace・Android）がなければ、ビルドを止める

| 値 | 使う所 |
|---|---|
| [Title] Text | 「（略名）について」の画面のアプリ名（`AppProfile.TITLE`） |
| [Title] ShortText | アプリの表示名（ホーム画面などに出る名前）、メニューの「（略名）について」（`AppProfile.SHORT_TITLE`） |
| [Version] Text | アプリのバージョン名（versionName）、「（略名）について」の画面のバージョン（`AppProfile.VERSION`） |
| [Version] Number | アプリのバージョンの番号（versionCode）（`AppProfile.VERSION_NUMBER`） |
| [Copyright] Text | 「（略名）について」の画面の著作権表示（`AppProfile.COPYRIGHT`） |
| [Copyright] Name | 「（略名）について」の画面の著作権表示の 2 行目（`AppProfile.AUTHOR`。なくてもよい） |
| [AppId] Namespace | Java のコードのパッケージ名（`net.gorry.mase`）。書いてあるとおりの順で使う |
| [AppId] Android | Android のアプリ ID（`net.gorry.mase`）。書いてあるとおりの順で使う |
| [AppId] DebugSuffix | デバッグ用のビルドで、アプリ ID とアプリの表示名に付ける言葉（今の値は `debug`）。なくてもよい |
| [URL] Project | `AppProfile.PROJECT_URL`（今は使っていない。なくてもよい） |
| [URL] Release | `AppProfile.RELEASE_URL`。アプリの情報の「配布元」（なくてもよい） |
| [URL] Notice | `AppProfile.NOTICE_URL`。アプリの情報の「NOTICE」（なくてもよい） |

- `Profile.ini` の値は書き換えない
- [AppId] Namespace と [AppId] Android は、今は同じ値だが、別の項目として扱う（パッケージ名と、アプリ ID）
  - 以前は、[AppId] Namespace だけがあり、細かい側から書いた値（`mase.upa.jp`）を、逆順にしてアプリ ID（`jp.upa.mase`）にしていた。ユーザーの指示で、名前と書く順を改めた
- デバッグ用とリリース用の違い（[AppId] DebugSuffix が `debug` のとき）

| | アプリ ID | アプリの表示名（ホーム画面などに出る名前） |
|---|---|---|
| リリース用 | `net.gorry.mase` | `mase` |
| デバッグ用 | `net.gorry.mase.debug`（「.」でつないで、後ろに付ける） | `mase debug`（空白でつないで、後ろに付ける） |

  - アプリ ID が違うので、2 つは別のアプリになる。同じ端末に、両方を入れておける。設定（色など）も、別々に持つ
  - [AppId] DebugSuffix がないとき・空のときは、デバッグ用にも何も付けない
  - アプリの中の表示（メニューの「（略名）について」、アプリの情報）は、デバッグ用でも変えない
- Java のパッケージ名（`net.gorry.mase`）は、ソースコードに書いてある（フォルダーは `app/src/main/java/net/gorry/mase/`）。`Profile.ini` からは作らない
  - ビルドのときに、[AppId] Namespace が、ソースコードのパッケージ名と同じかを確かめ、違えばビルドを止める。[AppId] Namespace を変えるときは、ソースコードのパッケージ名（フォルダー、各ファイルの先頭、レイアウトの中のビューの名前、C のコードの関数の名前）も、合わせて変える

## ビルド
- `gradlew assembleDebug` で、デバッグ用の APK を `app/build/outputs/apk/debug/app-debug.apk` に作る
- Android SDK の場所は、環境変数 `ANDROID_HOME` で指定する
- LAME のソースの取得
  - LAME のソースは、リポジトリに入れていない。ビルドのとき（`fetchLame`。ふつうのビルドの最初に、自動で動く）に、配布元のソースパッケージを取ってきて、リポジトリ直下の `third_party/` に置く

| 場所 | 内容 |
|---|---|
| `third_party/lame-3.100.tar.gz` | 配布元のソースパッケージ。なければ、`https://downloads.sourceforge.net/project/lame/lame/3.100/lame-3.100.tar.gz` からダウンロードする |
| `third_party/lame-3.100/` | 上から、要る部分だけを取り出したもの（`libmp3lame/` の `.c`・`.h`、`include/lame.h`、`COPYING`・`LICENSE`・`README`） |

  - ソースパッケージは、SHA-256（`ddfe36cab873794038ae2c1210557ad34857a4b6bdc515785d1da9e175b1da1e`）で確かめる。違うときは、ビルドを止める
  - ネットワークがないとき・配布元から取れないときは、同じファイルを、手で `third_party/` に置けばよい（ダウンロードせずに、それを使う）
  - 一度取り出したら、次からは何もしない。置き場所は `build/` の外なので、clean でも消えない（リリースパッケージを作るたびに、取り直さずに済む）
  - 版を変えるときは、`app/build.gradle` の、版の番号と SHA-256 を変える
- `gradlew assembleRelease` で、リリース用の APK を `app/build/outputs/apk/release/app-release.apk` に作る
  - 署名の鍵と設定は、リポジトリ直下の `keystore/` に置く。秘密の情報なので、リポジトリには入れない（`.gitignore` で外してある）
  - `keystore/keystore.properties` の項目

| 項目 | 内容 |
|---|---|
| `storeFile` | 鍵のファイルの名前（`keystore/` の中のファイル） |
| `storePassword` | 鍵のファイルのパスワード |
| `keyAlias` | 鍵の別名 |
| `keyPassword` | 鍵のパスワード。なければ、`storePassword` と同じとみなす |

  - `keystore/keystore.properties` があれば、その鍵で署名した APK ができる。項目が足りないときや、鍵のファイルがないときは、ビルドを止める
  - `keystore/keystore.properties` がなければ、署名のない APK ができる（そのままでは、端末に入れられない）
  - デバッグ用の APK とは、署名が違う。デバッグ用が入っている端末に、リリース用を上書きでは入れられない（いったんアンインストールする。アプリの設定は消える）
- `gradlew releasePackage` で、リリースパッケージを作る
  - 必ず、前のビルドの結果を消してから（clean）、リリース用を新しく全部ビルドし直す。その後、できた APK を、リポジトリ直下の `release/` に置く
  - ファイル名は `[アプリ名]_android_[バージョン].apk`。アプリ名は `Profile.ini` の [Title] ShortText、バージョンは [Version] Text（例：`mase_android_2026.1128.1.apk`）
  - `keystore/keystore.properties` がないときは、署名できないので、止める
- 対象の Android：minSdk 34（Android 14）、targetSdk 35、compileSdk 36
- Java の外のライブラリ（AndroidX を含む）は、今は使っていない。画面は Android 標準の View で作っている
- C のライブラリは、LAME を使っている。NDK（29.0.14033849）と CMake（3.22.1）でビルドする。対象の ABI は arm64-v8a・armeabi-v7a・x86_64
  - APK には、`libmp3lame.so`（LAME）と `libmasemp3.so`（橋渡し）が入る
